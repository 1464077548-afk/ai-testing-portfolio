# AI 测试工程作品集

> 从传统功能测试转向**测试开发 / AI 测试**的实战记录与可运行工程。
> 不是一个 demo，是一套**能跑、能红、红了有证据**的自动化测试体系。

---

## 这个项目是什么

一个测试工程师用 12 周时间，把自己从「写用例、点页面」改造成「设计测试体系、让自动化被团队信任」的完整过程。

里面四个子工程各自独立可运行，合起来覆盖了接口、UI、性能、安全、契约、CI/CD 六个层次，
以及一个贯穿始终的工程命题：**自动化报告上的绿色，凭什么可信？**

## 快速开始

最省事的入口是主工程：

```bash
cd gitlab-qa
# 依赖装在独立环境里，别污染全局解释器
conda create -n gitlab-qa python=3.11 -y && conda activate gitlab-qa
python -m pip install -e ".[dev]"
python -m playwright install chromium   # 有 Edge/Chrome 可跳过，会自动回退
python tools/doctor.py          # 环境自检：能不能连上实例、依赖齐不齐
python tools/run.py --suite smoke
```

**没有真实 GitLab 也能跑**——内置了一个替身服务：

```bash
python tools/run.py --suite all --mock
```

## 两个环境坑（实测踩过，都写进代码注释了）

- **清理动作被安全策略掐断进程**：部分企业终端 / DLP 会拦截批量删除，
  表现是"跑到 100% 却没有汇总行、退出码 1"——看着像用例全崩，实际是收尾清理被拦。
  用 `python tools/run.py --suite all --keep-results`（只追加不清理）即可绕开。
- **覆盖率分片必须按批次隔离**：并行跑时每个 worker 各写一份分片、主进程合并。
  早期版本会把**历史残留**分片一起并进来：覆盖率虚高，收尾还要删几十个旧文件，
  正好触发上一条。现在分片带批次号，只并本轮。

## 这个工程想证明什么

自动化测试最常见的失败不是"跑不起来"，而是**跑起来了但没人信**。所以设计上刻意做了几件事：

- **对假绿零容忍**。缺第二身份的越权用例一律 `skip`，绝不让位 `pass`——
  用管理员身份访问管理员端点永远返回 200，那种断言是恒真的，等于没测。
- **失败即证据**。UI 失败自动附截图 + trace；接口失败附完整请求/响应日志；
  性能失败附采样明细。断言只说"期望 403 实际 200"，你还得再查一遍。
- **抖动要被记账**。重试用例的次数会写进报告和 `artifacts/flake/reruns.jsonl`——
  悄悄重试等于把不稳定藏起来。稳定性是**采样出来的**（重复 N 轮四类判定：
  稳定 / 持续失败 / 抖动 / 无有效数据），不是单次结果。
- **门禁分层**。PR 门禁只放快的、确定的；性能与依赖扫描走定时——
  把噪声放进门禁，只会让所有人学会无视红灯。

## 安全说明

- **`.env` 永不入库**（顶层与各子目录 `.gitignore` 双重拦截，含 PAT 与实例密码）。
  请复制 `.env.example` 后自行填写。
- `tests/security/` 的用例带**目标白名单守卫**：只允许对自己拥有的实例执行，
  指向其他地址会跳过。自动化安全测试一旦能指向任意目标，性质就变了。
- 部署脚本的 root 密码**从环境变量读取**，留空即报错退出，不硬编码；
  PAT 明文默认**随机生成**。

## 许可与边界

学习用途。安全测试部分请仅在你自己拥有的环境执行。
